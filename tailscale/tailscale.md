# tailscale — 원격 머신 접속 진단·설치 (Self-Contained)

원격 머신에 **지금 붙을 수 있는지**를 추측 없이 판정하고, 못 붙으면 **어느 계층에서 막혔는지**를 알려주기 위한 단일 근원(SSOT, Single Source of Truth). 본 파일 1개로 자체 완결.

## 설치 위치

- **본 파일**: `~/.claude/tailscale/tailscale.md` (전역 — 접속은 프로젝트가 아니라 머신 단위 문제)
- **진단 스크립트**: `~/.claude/tailscale/tailscale-doctor.sh`
- 본 파일이 위 경로에 없으면 본 규칙은 활성화되지 않는다.

## 모토 — 붙는지 안 붙는지를 추측하지 않는다

"연결이 안 된다"는 관측이 아니라 증상이다. 원인은 **미설치·데몬 정지·미인증·상대 꺼짐·SSH 미구성** 중 하나이며, 조치가 전부 다르다. 계층을 판정하지 않고 재시도하는 것은 정보를 얻지 못하는 반복이다.

## 무엇을 해결하고, 무엇을 해결하지 못하는가

| 해결한다 | 해결하지 못한다 |
| --- | --- |
| 방화벽·NAT 뒤에 있는 머신에 고정 주소로 접근 | **상대 머신이 꺼져 있는 것** |
| 공인 IP·포트포워딩 없이 SSH·파일 전송 | 상대에서 오래 걸리는 작업을 붙어 있는 동안 끝내는 것 |
| 머신 이름으로 접속(IP 암기 불필요) | 세션이 끊기면 사라지는 작업 지시 |

**오른쪽 열은 접속 도구로 풀 수 없다.** 실기(bench)에 붙은 머신은 전원이 상시 켜져 있지 않고, 접속이 되는 순간에도 그 세션이 유지된다는 보장이 없다. 이 경우는 접속을 기다리지 말고 **비동기 작업 지시 채널로 전환**한다(§4).

---

## 1. 실패 계층 — 진단은 항상 이 순서 (★ 강제)

위에서부터 판정하고, **처음 실패한 계층에서 멈춰서 그 조치만** 한다. 아래 계층을 건너뛰고 추측하지 않는다.

| 계층 | 무엇이 막혔나 | 판정 명령 | 실패 시 조치 |
| --- | --- | --- | --- |
| **L0** | 미설치 | `command -v tailscale` | §2 설치 |
| **L1** | 데몬 정지 | `systemctl is-active tailscaled` | `sudo systemctl enable --now tailscaled` |
| **L2** | 미인증·키 만료 | `tailscale status` 가 `Logged out`/`NeedsLogin` | §3 인증 |
| **L3** | **상대가 오프라인** | `tailscale status` 의 해당 피어 행 | §4 — 접속 포기, 비동기 전환 |
| **L4** | SSH 미구성 | `ssh -o BatchMode=yes <피어> true` | §5 SSH 구성 |

진단 스크립트(§6)가 이 순서를 그대로 수행하고 계층별 종료 코드로 회신한다.

**L3 가 가장 흔하다.** 실기 머신은 대개 꺼져 있고, 이때 L0~L2 를 재점검하는 것은 낭비다. 피어 행의 `offline, last seen ...` 이 그 자체로 결론이다.

## 2. 설치 (L0 조치)

### Linux (Ubuntu·Debian 계열, arm64 포함)

```bash
curl -fsSL https://tailscale.com/install.sh | sh
```

공식 설치 스크립트가 배포판·아키텍처를 판별해 apt 저장소를 등록하고 설치한다. Jetson(Orin 계열) 등 arm64 도 동일하다. 설치 후 데몬은 자동으로 `enable --now` 상태가 되며, 아니면 L1 조치를 수행한다.

수동으로 저장소를 등록한 환경에서는 `/etc/apt/sources.list.d/tailscale.list` 가 존재하고 `apt list --installed | grep tailscale` 로 확인된다. 갱신은 `sudo apt update && sudo apt install --only-upgrade tailscale`.

### Windows

공식 배포 페이지의 설치 파일을 사용한다. 설치 후 트레이 아이콘에서 로그인하면 §3 이 끝난 것과 같다.

### 설치 확인

```bash
tailscale version          # 버전 출력
systemctl is-active tailscaled   # active
```

## 3. 인증 (L2 조치)

```bash
sudo tailscale up
```

출력된 URL 을 브라우저에서 열어 **tailnet 소유 계정**으로 승인한다. 화면이 없는 머신(헤드리스 실기)은 URL 을 다른 기기에서 열면 된다.

- 재부팅해도 인증은 유지된다. 매번 로그인해야 한다면 데몬이 `enable` 되지 않은 것이므로 L1 을 본다.
- 관리 콘솔에서 노드 키 만료를 켜 둔 tailnet 은 일정 기간 후 재인증이 필요하다. 실기·서버처럼 사람이 못 붙는 머신은 **키 만료를 끄는 것**이 정석이며, 그러면 이 계층은 다시 문제되지 않는다.
- 헤드리스 자동 온보딩이 필요하면 관리 콘솔에서 발급한 auth key 로 `sudo tailscale up --authkey <key>`.

## 4. 상대가 오프라인일 때 (L3 조치) — ★ 대기 금지

`tailscale status` 의 피어 행이 `offline, last seen <시각>` 이면 **접속으로 풀 문제가 아니다.** 여기서 할 일은 다음 둘 중 하나다.

1. 머신을 켤 수 있는 사람에게 전원 상태를 확인한다.
2. **작업을 비동기 지시로 남긴다** — 지시를 파일로 적어 저장소에 올려 두면, 그 머신이 다음에 켜졌을 때 세션 시작 시점에 그 지시를 받는다. 붙어 있는 동안 끝내야 한다는 제약이 사라진다.

`last seen` 이 수 분 전이면 간헐 운용(작업 중 전원 on/off) 이고, 며칠 전이면 장기 미사용이다. 전자에 대해 재시도 루프를 도는 것은 특히 낭비다 — 켜지는 시점을 예측할 수 없다.

## 5. SSH 구성 (L4 조치)

접속 대상은 **머신 이름**으로 지정한다. MagicDNS 가 켜진 tailnet 에서는 짧은 이름이 그대로 해석되고, 아니면 `<머신이름>.<tailnet>.ts.net` 전체 이름 또는 `100.x.y.z` 주소를 쓴다.

```bash
tailscale status            # 이름·주소 확인
ssh <계정>@<머신이름>
```

두 가지 방식이 있다.

| 방식 | 무엇 | 언제 |
| --- | --- | --- |
| 일반 SSH | 상대의 `sshd` + 공개키 | 이미 키를 배포해 둔 머신 |
| Tailscale SSH | `tailscale up --ssh` 로 상대가 활성화, 접근 권한은 관리 콘솔 ACL | 키 배포 없이 붙어야 할 때 |

처음 붙는 머신은 `~/.ssh/config` 에 항목을 만들어 두면 이름·계정·키를 매번 적지 않아도 된다. `~/.ssh/known_hosts` 에 항목이 없다는 것은 **아직 한 번도 붙은 적이 없다**는 뜻이므로, 접속 실패를 네트워크 문제로 단정하기 전에 이것부터 본다.

## 6. 진단 스크립트

```bash
bash ~/.claude/tailscale/tailscale-doctor.sh [피어이름]
```

§1 의 계층을 순서대로 판정하고, **처음 실패한 계층의 조치를 출력**한 뒤 그 계층의 종료 코드로 끝난다. 피어 이름을 생략하면 L0~L2(자기 머신 상태)까지만 본다.

| 종료 코드 | 의미 | 안내 |
| --- | --- | --- |
| `0` | 접속 가능 | — |
| `10` | 미설치 | §2 |
| `20` | 데몬 정지 | L1 조치 |
| `30` | 미인증·키 만료 | §3 |
| `40` | 피어 오프라인 | §4 — 비동기 전환 |
| `50` | 피어 온라인·SSH 실패 | §5 |
| `60` | 피어 이름을 tailnet 에서 찾을 수 없음 | 이름 오타 또는 미가입 |

종료 코드가 계층과 1:1 이므로 호출한 쪽이 출력 문자열을 파싱하지 않고 분기할 수 있다.

## 7. 금지 사항

- 계층 판정 없이 재시도·재부팅·재설치하는 것.
- L3(상대 오프라인) 에서 켜질 때까지 대기 루프를 도는 것.
- 이 문서나 스크립트에 **tailnet 이름·노드 이름·`100.x` 주소·auth key 를 적는 것.** 본 번들은 외부 조직 저장소로 미러되므로 사설망 구성이 그대로 공개된다. 실제 값은 실행 시 `tailscale status` 로 얻는다.
- auth key 를 저장소·로그·명령 이력에 남기는 것.
