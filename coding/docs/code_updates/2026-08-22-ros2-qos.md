# 2026-08-22 — pub/sub 생성 시 QoS 결정 규칙 전달 (ros2-qos 훅)

## 무엇을

`coding/hooks/coding-ros2-qos.py`(PostToolUse) 신설 `⟦훅:ros2-qos⟧`. 추가된 텍스트에서
`create_publisher`/`create_subscription` 을 감지하면 RxO 호환 규칙·관례 프로파일 3종·
표 등재 항목(A-1/A-2/A-6)을 그 자리에 낸다. **차단하지 않는다.**

부수로 `check-mapping.sh` 의 태그 정규식 결함을 고쳤다.

## 왜

QoS 서술은 `domains/ros2-coding.md` §1 에 두 줄뿐이고("맞춘다"·"관례") 강제가 없다.
판정 규칙(RxO 매트릭스)은 `code_review/domains/ros2-review.md` A-6 에만 있어 코드 리뷰를
돌리는 턴이 아니면 적용되지 않는다. 두 경로 다 기억에 의존하므로 QoS 는 매번 지시로
맞춰져 왔다.

표 등재도 절반이다 — 실측(Big-AMR): 코드 pub/sub 194건 대비 표 행 149건이고, 그중
루트 정본·패키지 병기 이중 기록이 섞여 있어 고유 행은 그 절반 수준.

## 어떻게

**판정하지 않고 전달만 한다.** 실측 표본에서 토픽이 리터럴인 호출은 5개 중 2개뿐이고
나머지는 변수·f-string 이다. 정적 판정은 절반 이상을 놓치며, 놓친 것을 조용히
통과시키면 "검사했다"는 착각만 남는다(같은 형태의 실패를 인벤토리 게이트에서 이미
겪었다 — 산문 인용을 등재로 오판한 114건). 안내 내용은 고정이라 파싱 정확도와 무관하게
항상 옳다.

발동 조건은 `coding.md` + `domains/ros2-coding.md` 가 **둘 다** 설치된 프로젝트. 문서
파일(.md) 안의 예시 코드는 확장자로 걸러 대상에서 뺀다.

## 함께 고친 것 — check-mapping 태그 정규식

`⟦CI:[a-z][a-z-]*⟧` · `⟦훅:[a-z][a-z-]*⟧` 이 **숫자를 받지 않아** `ros2-qos` 처럼 id 에
숫자가 들면 태그를 달아도 "무태그 훅"으로 보고했다. `[a-z][a-z0-9-]*` 로 교정.
`coding.md` 자체 점검의 같은 grep 도 함께 고쳤다.
