# 2026-08-10 — inventory-gate 가 vendored 패키지를 표 요구에서 면제

## 무엇을

`covering_tables` 가 빈 결과일 때(표 없음) 차단하기 전에 `vendored_pkg()` 를 확인하고,
조상 패키지에 `LICENSE` 가 있으면 통과시킨다. 표가 이미 있는 vendored 패키지는
기존대로 선독을 요구한다(면제 대상은 "표 작성 요구"뿐).

## 왜

배포된 2대에서 훅을 실제 저장소에 돌려 측정한 결과:

| | Big-AMR | LGIT-C6-Cobot |
| --- | --- | --- |
| 코드 파일 | 985 | 1282 |
| 표 작성 요구 | 802 (81%) | 992 (77%) |
| ├ vendored | 391 | 363 |
| ├ git 미추적 | 62 | 112 |
| └ 우리 코드 | 349 | 517 |

차단의 47~56%가 `panda-firmware`·`OrbbecSDK_ROS2`·`realsense-ros` 등 우리가
유지보수하지 않는 패키지였다. 그 상태로 표를 채우면 안 써도 될 표를 쓰거나 `.allow` 를
수백 줄 쌓게 되고, 그 습관이 정작 필요한 차단까지 무력화한다.

## 어떻게

- `VENDOR_MARKERS = ("LICENSE", "LICENSE.txt", "LICENSE.md", "LICENCE")`
- `vendored_pkg(base, rel)`: 대상의 조상을 base 직전까지 거슬러 올라가며 marker 탐색
- `gate_write`: `not tables` 분기에서 `lenient` 다음 순서로 확인

판정 근거에서 **뺀 것 2가지**와 사유:

- **저장소 루트의 LICENSE** — 우리 저장소가 오픈소스면 전 파일이 면제돼 게이트가 통째로
  죽는다. `while len(d) > len(base)` 로 루트를 순회에서 제외한다.
- **git 미추적 여부** — 새로 만드는 파일이 미추적이므로, 이를 면제 근거로 쓰면 §2 의
  "신규 파일도 계획 단계에서 표 생성"이 뚫린다.

## 검증

`coding/tests/inventory-gate.test.sh` 47건 통과. 신설 3건:

- `T15c` 조상에 LICENSE → 표 요구 면제
- `T15d` 루트 LICENSE 는 근거 아님 → 차단 유지 (전체 무력화 방지)
- `T15e` vendored 라도 표가 있으면 선독 요구
