# 2026-08-10 — record-gate 에 이력 기록 확인 추가

## 무엇을

`coding/hooks/coding-record-gate.py` 의 Stop 판정을 **표 갱신 단독**에서 **표 갱신 +
이력 기록 각각 확인(AND)** 으로 확장했다. 둘 중 하나라도 빠지면 종료를 1회 막고,
빠진 쪽만 골라 안내한다.

- 표 갱신: 고친 코드의 커버 표를 같은 턴에 고쳤는가 (기존)
- 이력 기록: `code_updates/` entry 를 같은 턴에 썼는가 (신규). 표 유무와 무관

## 왜

워크스페이스의 v1 훅 `stop_check_code_record_reflected.py` 가 유일하게 잡던 것이
`code_updates/` 기록이었다. v1 은 legacy 이고 v3 번들이 최종이므로, v1 을 끄기 전에
그 커버리지를 v3 로 옮겨야 잃는 것이 없다.

다만 v1 의 판정은 `code_updates/` **또는** `inventory.md` 의 OR 이라 이력 한 줄만
쓰면 표는 끝내 안 고쳐도 통과했다. 그 OR 이 부채가 빠져나가는 경로였으므로 v3 는
AND 로 옮긴다 — 담당이 다른 두 산출물이라 하나가 다른 하나를 대신하지 않는다.

## 어떻게

- `main()`: `logged`(이번 턴 수정 경로 중 `code_updates/` 포함 여부)와
  `edited_code`(수정된 코드 파일 목록)를 산출. 통과 조건을
  `not stale` → `not stale and (logged or not edited_code)` 로 변경
- 메시지를 두 절(`▸ 함수표를 갱신하지 않았습니다` / `▸ 수정 이력을 기록하지
  않았습니다`)로 분리해 빠진 쪽만 출력

## 검증

`coding/tests/record-gate.test.sh` 18건 통과. 신설 3건:

- `S2b` 표만 갱신하고 이력 미기록 → 차단, 표 요구는 출력하지 않음
- `S7` 표 없는 파일도 이력은 요구(표 요구는 게이트 소관이라 이중 경보 금지)
- `S7b` 표 없는 파일 + 이력 기록 → 통과

회귀: inventory-gate 43 · reminder-inject 16 · comment-gate 15, `check-mapping` 정합.
