# remote_instruction — 원격 PC 작업 지시 채널 (Self-Contained)

원격 PC 에서 수행할 작업 지시를 **파일로 전달하고 종결까지 추적**하기 위한 단일 근원(SSOT, Single Source of Truth). 본 파일 1개로 자체 완결.

## 설치 위치

- **본 파일**: 대상 프로젝트의 `docs/claude_guideline/remote_instruction/remote_instruction.md`
- **지시 내용**: 대상 프로젝트의 `docs/remote_instruction/`
- 본 파일이 위 경로에 없으면 본 채널은 활성화되지 않는다.

## 왜 필요한가

원격 PC 는 실기(hardware)가 붙어 있어 작업이 그쪽에서만 가능한데, SSH(Secure Shell) 로 붙어 대화형 세션을 끌고 가는 방식은 세션이 끊기면 지시도 함께 사라진다. 지시를 **파일에 값으로 박아** 두면 세션 경계를 넘어 살아남는다.

단, 파일로 쌓아두기만 하면 더 나쁜 상태가 된다. 무엇이 처리됐는지 판별할 수 없는 지시 더미는 다음 세션에게 "전부 다시 하거나 전부 무시하라"는 두 선택지만 남긴다. **종결 규약이 채널의 본체**이고 폴더는 그릇일 뿐이다.

## 모토 — 지시는 값으로, 종결은 색인으로

- 지시를 만들 때 **완료 조건을 같이 적지 못하면 그 지시는 보내지 않는다.**
- 미완료 상태(보류)에는 **재개 조건을 반드시 붙인다.** 출구 없는 보류는 금지한다.
- 처리 여부 판단은 색인 1개만 본다. **색인에 없으면 미처리다.**

## 1. 전달 경로

git 저장소를 통해 전달한다. 별도 인프라를 쓰지 않는다.

| 방향 | 주체 | 동작 |
| --- | --- | --- |
| 발신 | 로컬 | 지시 파일 작성 → commit → push |
| 수신 | 원격 | pull → 세션 시작 시 미처리 지시 자동 주입 → 수행 |
| 회신 | 원격 | 상태·근거 기록 → commit → push |

**지시 내용을 자산·번들 저장소에 두지 않는다.** 자산 저장소는 외부 조직으로 미러되는 경우가 있어 작업 지시가 그대로 외부에 공개된다. 지시는 항상 **작업이 실제로 벌어지는 대상 프로젝트 저장소** 안에 둔다.

## 2. 지시 파일 형식

지시 1건 = 파일 1개. 경로는 `docs/remote_instruction/YYYY-MM-DD-NNN.md` (`NNN` 은 그날의 3자리 일련번호).

```markdown
---
id: 2026-08-04-001
target: <원격 호스트 또는 프로젝트 식별자>
kind: 실행 | 조사
status: 대기
created: 2026-08-04
done_when: <관측 가능한 완료 조건 — 비워둘 수 없음. 작성법은 kind 별로 다름(§3.1)>
evidence: []
---

## 지시 원문

(사용자 지시를 **원문 그대로**. 요약·해석·재작성 금지.)

## 배경 (선택)

(원격이 판단에 필요한 맥락. 없으면 절을 비우고 "(없음)" 1줄.)

## 수행 기록

(원격이 append. 시도·관측·결과를 시간순으로.)
```

절 이름은 고정한다(색인 자동 생성·grep 일관성).

**지시는 자기 완결이어야 한다.** 대상 머신에 규칙·번들·문서가 설치되어 있다고 가정하지 않는다 — 특히 새 머신을 셋업하는 지시는 그것들이 아직 없는 상태에서 실행된다. "§3 을 따르라", "가이드대로 하라" 대신 **실행할 명령과 판정 기준을 지시 파일 안에 그대로 적는다.** 참조로 대신하면 수신 측이 참조 대상을 못 찾고 추측으로 메운다.

## 3. 완료 조건 (★ 강제 게이트)

`done_when` 은 **제3자가 보고 참·거짓을 판정할 수 있어야** 한다. 판정 주체가 정해지지 않는 표현은 완료 조건이 아니다.

| 나쁜 예 | 왜 안 되는가 | 좋은 예 |
| --- | --- | --- |
| "잘 동작하면" | 판정 주체·기준 없음 | "`ros2 topic hz /mcl_pose` 가 20Hz 이상을 30초 연속 유지" |
| "안정화되면" | 종료 시점 없음 | "동일 조건 3회 반복에서 전부 재현" |
| "확인되면" | 무엇을 확인하는지 없음 | "`build/` 에 `libcan_relay.so` 생성 + `ldd` 미해결 심볼 0" |
| "검토 후 판단" | 지시가 아니라 위임 | "옵션 A/B 각각 측정치를 표로 회신(판단은 로컬)" |

관측 가능한 완료 조건의 형태는 대체로 넷 중 하나다 — **파일·산출물의 존재**, **명령의 종료 코드**, **로그·측정치가 명시 범위 안**, **정해진 횟수의 재현**.

`done_when` 이 비어 있거나 위 나쁜 예에 해당하면 그 파일은 채널에 올리지 않는다. 검사는 §8 자체 점검이 수행한다.

### 3.1 지시는 2종 — 완료 조건 작성법이 다르다

`kind` 필드로 구분한다. **이 구분을 빠뜨리면 조사형 지시가 영구 보류로 쌓인다.**

| kind | 무엇을 시키는가 | `done_when` 은 무엇으로 쓰는가 |
| --- | --- | --- |
| `실행` | 산출물·상태를 만들어라 | 그 산출물·상태의 성립 |
| `조사` | 참인지 확인하라 / 측정하라 | **관측 절차의 수행 + 측정치 회신** |

조사형에서 **결과값의 참·거짓은 종결 조건이 아니다.** 가설이 반증되어도 관측을 수행하고 값을 회신했으면 그 지시는 `완료` 다. 판정은 로컬이 회신을 받아서 한다.

- 틀림: `done_when: "재호밍 없이 위치 오차 < 5mm 를 5회 연속 재현"` — 반증이 나오면 완료로 올릴 수 없어 보류로 밀린다.
- 맞음: `done_when: "무재호밍 조건에서 위치 오차를 5회 측정하여 5개 값 전부 회신(참·거짓 판정은 로컬)"`

### 3.2 분모는 로컬이 확정한다

대상 집합이 열린 지시("전부", "관련된 것들", "해당하는 항목")는 **원격이 분모를 자의로 정하게 만들어** 완료 판정이 흔들린다. 대상이 복수인 지시는 로컬이 **개수 또는 열거된 목록**을 `done_when` 에 박는다.

- 틀림: `done_when: "종결 가능한 항목이 전부 색인에 올라감"` — 무엇이 종결 가능인지가 이 작업의 산출물이라 순환이다.
- 맞음: `done_when: "지정한 40건 각각이 색인에 1행씩 매핑되거나 '미종결' 로 분류됨(미분류 0건)"`

분모를 지금 확정할 수 없으면 **분모를 세는 것 자체를 조사형 지시 1건으로 먼저 보낸다.**

### 3.3 사람만 할 수 있는 단계는 분모에서 뺀다

원격이 명령으로 끝낼 수 없는 단계(브라우저 승인, 관리 콘솔 설정, 전원·케이블 조작)가 지시 안에 섞이면, 그 단계를 `done_when` 의 통과 조건에 넣는 순간 **원격의 힘으로는 영원히 충족할 수 없는 완료 조건**이 된다.

사람 단계는 통과 조건이 아니라 **명시 회신 대상**으로 돌린다.

- 틀림: `done_when: "8단계 전부 통과"` — 그중 1단계가 콘솔 작업이면 완료 불가.
- 맞음: `done_when: "명령으로 가능한 7단계 통과 + 콘솔 단계의 처리 여부를 명시 회신"`

사람 단계가 **선행 조건**이라 그것 없이는 다음으로 못 가는 경우는 분모 조정이 아니라 §4 의 보류로 처리한다.

## 4. 상태 전이

상태는 네 가지뿐이며, 아래 전이 외의 이동은 금지한다.

| 전이 | 주체 | 필수 기재 |
| --- | --- | --- |
| 대기 → 진행 | 원격 | (없음) |
| 진행 → 완료 | 원격 | `evidence` 1개 이상 (파일 경로·커밋 해시·로그 발췌 중) |
| 진행 → 보류 | 원격 | `blocked_reason` + **`resume_when`(재개 조건)** |
| 보류 → 대기 | 로컬 | `resume_when` 이 충족됐다는 근거 1줄 |

보류↔대기는 **한 지시 안에서 여러 번 오갈 수 있다.** 사람 승인·콘솔 설정·발신 측 결정을 기다리는 지점이 여럿인 지시는 그때마다 보류로 돌린다. 왕복 횟수는 제한하지 않으며, 막힌 채 진행하거나 추측으로 메우는 것보다 항상 낫다. **사람을 기다리는 것은 정당한 보류 사유다.**

**보류에 재개 조건을 요구하는 이유**: 재개 조건이 없으면 보류는 영구 미판정이 된다. 내려가는 문만 있고 올라오는 문이 없는 상태에서는 아무리 관측을 반복해도 상태를 올릴 근거가 생기지 않는다. `done_when` 과 `resume_when` 은 같은 규칙(§3) 을 따른다.

완료 항목은 **삭제하지 않는다.** 삭제 대신 색인에서 완료로 표기하고 파일은 남긴다(재실험 방지의 근거가 여기에 있다).

## 5. 색인 — `docs/remote_instruction/INDEX.md`

채널 전체에서 **처리 여부를 판단하는 유일한 출처**다. 40개 파일을 재구성하지 않기 위해 존재한다.

```markdown
# 원격 작업 지시 색인

**이 표에 완료로 적히지 않은 것은 전부 미처리다.** 개별 파일이 무엇을 주장하든 이 표가 우선한다.

| id | target | 한 줄 요약 | status | 종결일 |
|----|--------|-----------|--------|--------|
```

지시 파일을 만들거나 상태를 바꾼 주체가 같은 커밋에서 색인 행도 갱신한다. 색인에 없는 지시 파일은 유실로 간주한다.

## 6. 세션 시작 주입

원격에서 "폴더를 열어보는 것"에 기대지 않는다. SessionStart 훅이 **미처리 항목만** 세션 컨텍스트로 주입한다.

- 주입 대상: `대기`, `보류` 항목만. 보류는 `resume_when` 을 함께 보여준다.
- **완료 항목은 주입하지 않는다.** 읽을 필요 자체를 없애는 것이 목적이며, 완료분을 같이 보여주면 다시 판별 비용이 생긴다.
- 미처리가 0건이면 침묵한다(no-op).
- 훅 미설치 환경은 수동으로 `docs/remote_instruction/INDEX.md` 를 연다.

## 7. 쓰기 주체 분리

같은 필드를 양쪽이 고치지 않게 하여 병합 충돌을 구조적으로 없앤다.

| 필드·절 | 쓰기 주체 |
| --- | --- |
| `target` · `done_when` · §지시 원문 · §배경 | 로컬(발신)만 |
| `status` · `evidence` · `blocked_reason` · `resume_when` · §수행 기록 | 원격(수신)만 |
| `INDEX.md` 행 | 그 행을 만든/바꾼 쪽 |

원격은 지시 원문을 고치지 않는다. 지시가 틀렸다고 판단되면 **보류로 돌리고 사유를 적는다**(원문 수정은 로컬의 권한).

## 8. 자체 점검

```bash
cd docs/claude_guideline/remote_instruction
bash checks/instruction-lint.sh ../../..
```

검출 항목 — `done_when` 누락·공란, `kind` 누락 또는 2종 외, 상태 값이 4종 외, `완료` 인데 `evidence` 0건, `보류` 인데 `resume_when` 없음, 색인에 없는 지시 파일, 색인 status 와 파일 status 불일치, `done_when` 에 열린 수량어("전부", "모두", "관련된") 가 수치·목록 없이 등장(§3.2).

## 9. 금지 사항

- 지시 내용을 자산·번들 저장소에 두는 것(외부 미러 유출).
- `done_when` 없이 지시를 올리는 것.
- 조사형 지시의 `done_when` 을 결과값의 참·거짓으로 쓰는 것(§3.1).
- 분모가 열린 채로 복수 대상 지시를 보내는 것(§3.2).
- 출구 조건 없는 보류.
- 완료 파일 삭제·덮어쓰기(append 만 허용).
- 원격이 지시 원문을 고치는 것.
- 색인 갱신 없이 상태만 바꾸는 것.
